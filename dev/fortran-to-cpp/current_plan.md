# Plan — Fortran → C++ translation

The **Plan** (paper §4.1): a human-seeded checklist of units for a targeted slice
of work, which agents edit to tick tasks off and record short notes. It is the
running record human and agent share across sessions, and the place per-file
outcomes (verified / translated / failed) are recorded after a run.

Legend: `- [ ]` untouched (no `.cpp` sibling yet); `- [x]` translated and wired
into CMake. A translated unit is **verified** only after the coverage probe fires
(`desired_spec.md` §6). Paths are relative to `$MCFM_HOME/src`. Order within a
directory is dependency-first; the Doxygen index
(`tools/build_roadmap.py`, `deps==0 && blind==0`) is the authority on readiness.

## How to use

- Run the `mcfm-translate` workflow (`args:{projectRoot, resolver:"graph",
  scope:"<dir>"}`): it indexes (Doxygen), resolves the next leaf layer, drafts +
  translates each file in parallel, then integrates and verifies serially.
- To refresh readiness by hand: `python3 tools/build_roadmap.py` regenerates
  `tools/assets/roadmap_metrics.tsv` and `tools/assets/symbol_index.json`.
- After a run, flip the boxes you cleared and add a one-line outcome note per unit.

## Working notes

- Units in `Mods/Need/Inc/Procdep` have no exercising benchmark — they can only be
  marked *translated*, never *verified* (Spec §5). Do not treat a graph leaf in
  those directories as a verifiable target.
- A unit whose coverage probe is UNCHANGED is only *provisionally* off-path
  (Spec §4.H); re-probe after its caller becomes C++.
- Report a suspected mistranslation as FAILED with the symptom rather than guessing
  a fix; a subtle numerical disagreement is escalated to a human (P2) — note it here.
